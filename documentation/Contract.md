# The Girl42 contract

Source: [`code/contracts/Girl42.sol`](../code/contracts/Girl42.sol)

`Girl42` is an OpenZeppelin `ERC721` + `Ownable` contract that can only ever hold **one token, with ID `1`**.

## Rules

- Only the **owner** (the address passed to the constructor — the deployer, in `deploy.js`) can mint or update metadata.
- The token can be minted **once**. A second `mintNFT` call reverts.
- The token's metadata is an IPFS URI stored in the contract. The owner can change it after minting.

## Functions

| Function | Who can call | What it does |
|---|---|---|
| `constructor(name, symbol, initialOwner)` | — | Sets the collection name/symbol and the owner. Deployed as `("Girl42", "G42", deployer)`. |
| `mintNFT(recipient, metadataURI)` | owner | Mints token `1` to `recipient` and stores `metadataURI`. Reverts if already minted or if `metadataURI` is empty. |
| `tokenURI(1)` | anyone | Returns the stored metadata URI. Reverts for any other ID, or before minting. |
| `exists()` | anyone | `true` once the token has been minted. |
| `getOnChainMetadata()` | anyone | Same value as `tokenURI(1)`. Reverts before minting. |
| `updateOnChainMetadata(newURI)` | owner | Replaces the stored metadata URI. Reverts before minting. |

All standard ERC721 functions (`ownerOf`, `transferFrom`, `approve`, …) are inherited from OpenZeppelin.

`metadataURI` is expected to look like `ipfs://<metadata hash>`. It points to a JSON file like this one (generated by `upload.js`, saved in `images/metadata.json`):

```json
{
  "name": "42Girl",
  "description": "NFT for the 42 school project TokenizArt. Drawn by Horzeau.",
  "image": "ipfs://<image hash>",
  "external_link": "https://gateway.pinata.cloud/ipfs/<image hash>",
  "artist": "jrenault"
}
```

Note: IPFS content can't change, so "updating" the metadata means uploading a new JSON file and pointing the contract at its new hash.

## Revert messages

| Message | Cause |
|---|---|
| `NFT already minted` | `mintNFT` called a second time. |
| `On-chain metadata cannot be empty` | `mintNFT` called with an empty URI. |
| `OwnableUnauthorizedAccount` (custom error) | A non-owner called `mintNFT` or `updateOnChainMetadata`. |
| `Only one NFT exists with ID 1.` | `tokenURI` called with an ID other than `1`. |
| `ERC721Metadata: URI query for nonexistent token` | `tokenURI(1)` called before minting. |
| `Token does not exist` | `getOnChainMetadata` / `updateOnChainMetadata` called before minting. |

## Tests

Source: [`code/tests/Girl42.test.js`](../code/tests/Girl42.test.js). Run with `npx hardhat test` (runs on a local Hardhat network, no ETH needed — but `.env` must still exist, see [Deployment.md](Deployment.md)).

- **Deployment:** correct owner, name and symbol; token not minted yet.
- **Minting:** owner can mint; second mint fails; non-owner mint fails; empty metadata fails.
- **Metadata:** `tokenURI` and `getOnChainMetadata` return the minted URI.
- **Updating metadata:** owner can update; updating before minting fails.
